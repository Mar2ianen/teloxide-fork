## Migration notes

- `get_me()` returns `BotFullInfo`. Fields for bot configuration move
  from `User` to `BotFullInfo`; `Me` remains a type alias.
- Expandable rich-quote input and incoming models contain recursively nested
  `blocks` instead of the former single `text` field.
- `set_my_settings()` supports all optional Bot API 10.5 settings.
  `CacheMe` invalidates its shared `get_me` cache after successful
  `set_my_settings()` and `set_my_name()`.
- `ChatFullInfo::active_usernames()` remains available for private,
  supergroup and channel chats (restored by PR #71).
- Bot API 10.4 breaking changes introduced in rc.1 continue to apply.
  See `MIGRATION_GUIDE.md` for both updates.

- [ ] All `CI succeeded` checks green on the **exact release-PR SHA**.
- [ ] `Deep Rust quality`: property/feature matrix, fuzz, coverage and
      mutation results reviewed; document skipped/time-limited mutants.
- [ ] `cargo package --list --locked` for core, macros and facade.
- [ ] `cargo publish --dry-run --locked -p teloxide-core`, subject to
      packaging validation and availability of registry dependencies.
- [ ] Verify crates.io ownership, ability to publish under package names
      `teloxide` and `teloxide-core`, and availability of required
      `teloxide-macros 0.11.2-rc.1`. GitHub prerelease is distinct from
      publishing crates.io packages; do **not** claim registry publication
      solely from GitHub tags.
- [ ] Check downstream compilation: `teloxide-ui` merged, `teloxide-antispam`
      merged, and `NedoBot` PR #176 reviewed. The downstream CI is advisory.
- [ ] Review `teloxide_tests` compatibility. Its published 0.4.0 version
      depends on Teloxide 0.17, so it cannot serve as a 0.21 RC gate without
      a port. Existing offline Bot API, property, fuzz and dispatcher
      regressions remain required.
- [ ] Merge release PR to `master`, tag **that exact commit** (annotated,
      immutable), then publish the GitHub prerelease.
- [ ] Publish crates in dependency order *only if registry rights and
      registry dependency versions are confirmed*. Otherwise document
      Git-only installation at the exact release tag.
